# Motif Card: Bounded TRUE Closure Routes

Updated: 2026-05-19

## Scope

Routes covered: `true:rewrite_chain:*`, `true:absorption_closure:*`, `true:absorption_closure:deep`, `true:equational_closure:*`, and opt-in `true:grind` as historical contrast.

## Mathematical Motif

These routes search a bounded fragment of the congruence closure generated by the hypothesis equation. Every edge in the search carries a concrete proof term. When the left and right frontiers meet, the solver joins the proof chains and emits a standalone Lean certificate.

## Trigger Summary

- `rewrite_chain`: short BFS over direct hypothesis rewrites from goal lhs to goal rhs.
- `absorption_closure`: absorption-like hypothesis; bounded bidirectional closure with a smaller pool.
- `deep_absorption`: same motif with deeper/time-capped settings after cheaper routes fail.
- `equational_closure`: broader bounded closure for non-absorption or late fallback cases.
- `grind`: disabled by default; historical tactic fallback only.

## Lean Rendering Sketch

```lean
import JudgeProblem

def submission : Goal := by
  intro G _ h
  intro x y z
  exact ((step1).trans (step2)).trans (step3)
```

Each `stepN` is produced by the solver from an explicit hypothesis rewrite under substitution and, where needed, congruence.

## Local Semantic Check

1. Parse the hypothesis and goal terms.
2. Generate candidate substitutions and term pools under strict bounds.
3. For every generated edge, retain both endpoint terms and a proof expression.
4. When frontiers meet, verify endpoint compatibility and join the proof path.
5. Render only checked paths.

## Limits

- Bounds are empirical: depth, frontier size, fill count, slack, and time budgets protect Marathon behavior.
- Increasing bounds without fixture evidence can waste shared Marathon time.
- Closure code has duplicated structure between absorption and equational routes; unifying it is a future refactor, not a first polish step.
