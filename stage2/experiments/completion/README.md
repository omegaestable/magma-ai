A dev tool — and, since 2026-08-21, the ancestor of a solver route. It proves
`eq1 ⇒ eq2` by completing the rewrite
system generated by `eq1` alone, trying to join `eq2`'s two sides after every
processed equation, and rendering the joining chain as a Lean `lemma_chain`
certificate that the repo's independent proof kernel then verifies.

## Why this exists

It closed rows nothing else could. The final nine official/HF rows
(`stage2/results/2026-08-12-final-nine-completion.md`) and the last three
`sample_200` holdouts were all derived with this, by hand, per row, after
equality saturation failed at every budget — `hard2_0073`'s collapse falls out
in 0.0 s here against 1336 s of `deep`-effort saturation that failed.

The reason is structural, and worth keeping: completion **derives new rules by
superposition and then rewrites with them**, whereas an e-graph only propagates
congruence over terms it has already built. When a search plateaus, ask what
class of inference it structurally cannot make.

## Provenance, and why it is here now

Until 2026-08-13 this lived only in `tmp_stage2_smoke/final-nine-2026-08-12/`,
which `.gitignore` excludes via `tmp*/` — **0 files tracked**. CLAUDE.md
described it as "the durable result worth carrying forward" and told the next
session to run it first on any fresh corpus, while it existed on exactly one

It now lives at a path `.gitignore` does not exclude, and `solve_row.py` derives
the repo root from its own location instead of hardcoding it. **It is not
committed yet** — `git status` still reports this directory as untracked as of
2026-08-13. Commit it; an uncommitted copy is exactly the state this move exists
to escape.

## Known gap: a derived collapse is discarded  — FIXED IN THE PORT, 2026-08-21

**This was the top next lever. It is done** (generalised past `x = y`; see the
banner). Kept because the reproduction below still runs and still shows the dev
tool's behaviour, which differs from the shipped route's. The
driver solves 4 of the final nine as shipped; the other five fail for one
reason.

`Eq.__init__` (`kb2.py:248-252`) orients an equation only when one side's
variables contain the other's:

```python
vl, vr = tvars(lhs), tvars(rhs)
if vr <= vl:  self.ori.append((lhs, rhs,  1, ...))
if vl <= vr and lhs != rhs:  self.ori.append((rhs, lhs, -1, ...))
```

For a **collapse** — `x = y` with two *distinct* variables — neither inclusion
holds, so the equation gets no orientation, never becomes a rewrite rule, and
`joinable()` (which works by `comp.normalize`) can never use it. The collapse is
derived and then thrown away.

Reproduced 2026-08-13:

```
$ python stage2/experiments/completion/solve_row.py hard2_0073 60
SATURATED after 12 equations, 0.0s (passive empty)
NO PROOF: processed=12 active=6 passive=0
   E12: xr82 = xr71        <-- the collapse, derived in 0.0 s, unused
```

This matters because collapse is the dominant shape on this frontier: CLAUDE.md
rail 5d records that **14 of 31** unsolved TRUE rows had `eq1 ⇒ (x = y)` with
the goal irrelevant, and `true:egg_collapse` exists precisely to exploit it.

The fix is not merely to orient `x = y` — as a rewrite rule it is unbounded and
would not terminate. It is to special-case it: if any derived equation equates
two distinct variables, the magma is trivial, every equation holds, and `eq2`
follows. The certificate is the recorded chain deriving the collapse plus the
instantiation closing `eq2` — the `lemma_chain` shape the renderer already
emits, and which `check_true_lemma_chain_certificate` already verifies, so no
new oracle surface is needed. Deliberately **not** applied here: it is an
algorithmic change and belongs with its own judge verification, not tacked onto
a QA pass.
