### v13 IS ALSO FALSE — and now the diagnosis is structural

Third hand-built cell, third hole. W6 fires at the **C** position, where its payload reading is wrong:

```
W  = J g0 g1
x  = J (J W g1) W                        -- tg x != 1, a1 (a1 x) = W = a2 x  (x passes W6's u-guard)
z  = J g0 x                              -- a2 z = x, a1 z = g0 = a1 (a1 (a2 x))  -> W6 fires on (x,z)
y  = J (E z (J g1 z)) z                  -- a2 y = z, a1 (a1 y) = z, W1 fires on (z,y)
profile W1,W1,W6,F,F     A = z  B = z  C = g1  D = J g1 y   R = J y (J g1 y)   expected x
```
`op x z` returns `a2 (a2 x) = g1` by W6 instead of `a1 (a1 z) = g0`, so the root's W6 guard
`a1 v = a1 (a1 (a2 u))` reads `g1 = g0` and nothing fires.

**The structural reason, and it rules out every non-recursive W6 guard.** W6's job is "the payload is not
in `v`, it is `a2 (a2 u)`", and it is correct exactly when `a1 v` really is `op (a2 (a2 u)) (a2 u)`. Any
*structural* approximation of that ("`a1 v` looks like `a1 (a1 (a2 u))`") is wrong as soon as the inner
product itself decoded by W6 — which nests without bound. So:

> **A rule whose result reads the payload out of `u` must certify `v` by RE-RUNNING the encoding.
> That guard is a recursive call; no shape test can replace it.**

This is the same lesson as `gen/NOTES_27859.md`'s "dead ends measured" section, reached independently:
a purely structural guard cannot know what an inner product decoded to.

```

DE / QEE / F0 / FR / WE     one rewrite lemma per branch
TR                          free ∨ (Q ∧ E) ∨ (D ∧ = a1 (a1 v)) ∨ (W ∧ recomputation ∧ = a2 (a2 u))

```

**Leaf tactic**: `have := congrArg sz e; simp only [q1J]; have := s2 _; omega` — every leaf. Four `rcases`
on `D`, no induction anywhere, no `grind`, no Mathlib.

**The three moves that made it work:**

1. **A different carrier, not a smaller rule set** (the reachability answer above).
2. **`CORE`, parameterised by two oracle hypotheses.** The `A decoded by D` and `A decoded by W` branches
   share their entire tail but differ in *why* two specific coincidences are impossible. Rather than
   duplicate ~60 lines, `CORE` takes them as hypotheses:
   `hbad : a1 (a1 y) = a2 y → op (op z y) y = J (op z y) y → False` and
   `hsd : a2 y = op z y → a1 (a1 y) = a2 y`.
   The D branch discharges both by rewriting `op z y = z` into `op (op z y) y = J (op z y) y`; the W
   branch discharges them by `A1L` on the recomputation fact. This is the general form of W3-7 when the
   general invariant does not exist but the *tail* is still shared.
3. **`exact`, not `rw`, for a rule lemma whose `a2 v = u` guard is `rfl`.** All six first-round errors
   were this: `rw [DE (d4 rfl rfl rfl rfl rfl)]` makes Lean unify the pattern `op (a2 ?v) ?v` (because
   `h2 : a2 v = u` is `rfl`, so `u := a2 v`), which does not match `op y (J ... y)` syntactically even
   though it is defeq. `exact DE (d4 rfl rfl rfl rfl rfl)` elaborates against the goal, which fixes `u`
   and `v` first, and also closes the trailing `a1 (a1 (J (J x z) y)) = x` that `rw`'s reducible-only
   `rfl` would not. **Rule: if a rule lemma's guards include `rfl` for `a2 v = u`, finish the product
   with `exact`, never `rw`.**
