## Real Lean 4 parsing constraint found (not documented in PLAYBOOK_PROOF.md, worth adding)

Tested directly (`gen/_mini_test.lean`, deleted after): **term-level function application via
juxtaposition needs at least one whitespace character before a parenthesized or `⟨...⟩`
argument.** `foo(u)`, `foo (u)(v)`, `Or.inl(rfl)`, `Or.inl⟨a,b⟩` ALL fail with
`error: unexpected token '('|'⟨'; expected command` (the parser treats the bare identifier as a
complete term and the following `(`/`⟨` as a new, unparseable command). Only **specific tactics
with their own bracketed sub-grammar** (`rw[`, `simp[`, `simp_all[`, `obtain⟨`, `exact⟨`,
`refine⟨`, `rintro⟨` — squeeze.py's existing list) tolerate zero space; ordinary term-position
application never does. So `) (` -> `)(` and `Or.inr ⟨`/`Or.inl ⟨`/`absurd ⟨` -> tight are BOTH
unsafe as blanket rules; do not retry either.
