### Why 23357 is harder than 23354, exactly
23354's `Ffree` holds because `op x (op x z)` repeats `x`: for it to be a top pair you would need
`x = J (J y'' x'') y''` and `op x z = J x'' (J x'' z'')` with `x'' = x`, i.e. `x = a2 (a1 x)` — refuted by size.
For 23357 the v-side is `op x (op y z)` with an **independent** `y`, and it IS a top pair whenever
```
x = J (J y' x') y'        (x is a free u-side for payload x')
op y z = J x' (J y' z')   (e.g. y := x', z := J y' z', with op y z free)
```
so **the law itself forces `op x (op y z)` to decode**. That is the whole extra difficulty and it is why
23357 needs the `Bs` ("v is a payload") rule family and 23354 does not. Do not look for an `Ffree`.

### The digest 23357 actually has
`X`'s "every decode returns `a1 v`" is false here: the `Bs` rules return `a2 (a1 u)` while `v` is a payload.
The uniform replacement (proved in `gen/_x23357_body.lean` as `SZ`, and cheap):
```lean
SZ (u v) : op u v = J u v ∨ sz (op u v) + 3 ≤ sz u ∨ sz (op u v) < sz v
```
(an L-rule returns `a2 (a1 u)`, a proper sub-subterm of `u`; an R-rule returns `a1 v`.)
Equivalently `op u v = J u v ∨ sz (op u v) + 2 ≤ max (sz u) (sz v)`.
