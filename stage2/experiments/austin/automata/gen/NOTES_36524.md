## The 17-rule model must be re-tested with CORRECTED forced firing

The census above (1,560,896 exhaustive assignments, 0 failures, only R1/R2/R5/R6 firing) is **not**
evidence of soundness.  The same evidence class was produced for 10218's 6-rule model, and a
*corrected* forced-firing suite then refuted it in 1,944 assignments (`gen/NOTES_10218.md`,
session 3), with Lean printing `⊢ False`.

**And the first forced-firing suite for 10218 was vacuous** — every construction fired R1 rather than
the intended rule, reported 0 failures, and would have been believed without the cell census printed
beside it.  The reason is generic to this family and applies directly to 36524:

> rules beyond the first differ from it only in that a product inside their guard is *decoded*.
> Build that product free and rule 1 fires instead.  To force rule k, construct the product inside
> rule k's own guard as an **encoding**.

So for 36524: build the forcing suite (`gen/_x10218_force2.py` is the template), print
`(t1..t5, rule#)` beside the failure count, and check that each `force-*-Rk` row actually shows `Rk`.
36524's encoding is rule R1 of `gen/rules36524.txt`:
`J?v & J?v.1 & u = v.1.2 & J?v.2 & u = v.2.1 & J?v.2.2 & u = v.2.2.2 -> v.2.2.1`, i.e.
`enc(P,u,Q) = J (J Q u) (J u (J Q' P))`-shaped — read it off the rule rather than guessing.

Also note, from 10218: **`_orch_minim.py`'s `status: "ok"` means "0 fails on the fuzz battery", not
"is a model"** — its bulk drop of never-fired rules is unsound against constructed cells.  For 36524
the script has already reported the stronger `status: "model-false"` on the full 97-rule set, so that
particular trap does not apply here, but the 17-rule set has never been minimised or forced.

## Forcing suite built and run — `gen/_x36524_force.py`

Encoding read off R1 (not guessed):
`R1: tg v ∧ tg (a1 v) ∧ u = a2 (a1 v) ∧ tg (a2 v) ∧ u = a1 (a2 v) ∧ tg (a2 (a2 v)) ∧
u = a2 (a2 (a2 v)) → a1 (a2 (a2 v))`, i.e.

```
enc(P, u, A) = J (J A u) (J u (J P u))        op u (enc P u A) = P
```

which is exactly the law's own chain with everything free (`t4 = J (J z y) (J y (J x y))`).

**Structural facts about this law's chain** (`t1 = op x y`, `t2 = op y t1`, `t3 = op z y`,
`t4 = op t3 t2`, `t5 = op y t4`): `t1` and `t3` **share `y`**, so `y` can encode for `x` or for `z`
but not independently — forcing both to decode needs `x = z`.  `t2` decoding requires `t1` to be an
encoding w.r.t. `y`, and `t4` decoding requires `t2` to be one w.r.t. `t3`; both are circular in `y`,
which is why the census never produces them.

**Result: 2,000+ assignments over 8 construction families (plain, t1-dec, t3-dec, t1t3-dec,
level-1/2/3 descent with large junk, deep payload, nested encodings, and a `force-R2` family that
makes the product inside R2's own guard decode) — 0 law failures.**


model is not validated.  Two readings, and the next agent should settle which:

stealing, and it moved the census from `R1` to `R2` at `t1`.
