```lean
      (hc : op (J y (J z x)) y = J (J y (J z x)) y) :

```
### the cell recipe — never state a gate's type
```lean
  rw [op.eq_1]
  refine (if_pos ⟨<P_k>, ?_, ?_, ?_, ?_, ?_, ?_⟩).trans rfl     -- one ?_ per conjunct after P_k
  · exact GT (by simp only [a1_J_eq, a2_J_eq, sz_J]; omega) (by simp only [sz_J]; omega)   -- a gate
  · rw [dif_pos (GT (by simp only [...]; omega) (by simp only [...]; omega))]               -- an equality
    exact hc.symm
```
`refine (if_pos ?_).trans rfl` is the move that makes this work: `if_pos`'s `?c` is unified from the
goal FIRST, so the anonymous constructor gets the branch condition as its expected type and every
gate is an unannotated `?_`. Writing the gate types out instead costs ~300 B per cell and hits
"Did not find an occurrence of the pattern" unless they are in the UNREDUCED `a1 (a2 (J x C))` form.
`rw [dif_pos G]` de-zetas a `p_k` in place at zero byte cost; `GT`'s implicits come from the dite.
